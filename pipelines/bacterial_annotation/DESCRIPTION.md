# Bacterial Annotation Pipeline Description

## Function

The pipeline accepts assembled bacterial contigs in FASTA format, selects
Prokka or Bakta through the validated `annotator` parameter, and normalizes
their differently named files into one BioAgent artifact contract.

```text
assembled contigs
  -> FASTA and parameter validation
  -> Prokka or Bakta
  -> engine-specific output validation
  -> stable output names, metrics, report, log, and raw ZIP bundle
```

No Biomni package is imported. The pipeline implements the capability directly
with local command-line tools.

## Parameters

Shared parameters:

- `annotator`: `prokka` (default) or `bakta`.
- `prefix`: safe output prefix.
- `genus`, `species`, `strain`: optional organism metadata.
- `cpus`: worker count from 1 through 256.
- `translation_table`: 4, 11, or 25; default 11.
- `locus_tag`: optional safe locus-tag prefix.
- `compliant`: request INSDC-compliant output rules.

Bakta-only parameters:

- `bakta_db_path`: existing compatible Bakta database directory. If empty,
  `BAKTA_DB` is used.
- `gram`: `+`, `-`, or `?`.
- `meta`: enable MAG/metagenome CDS prediction mode.
- `complete`: mark every input sequence as a finished replicon.
- `keep_contig_headers`: retain original FASTA identifiers.

Prokka-only parameter:

- `rfam`: enable Prokka's Rfam search.

The pipeline rejects unknown annotators, invalid translation tables, Bakta-only
parameters with Prokka, `rfam` with Bakta, and simultaneous Bakta `meta` and
`complete` modes. User values are passed as subprocess arguments; no shell or
arbitrary extra argument string is accepted.

## Stable outputs

- `annotation.gff`: GFF3 (`.gff` from Prokka or `.gff3` from Bakta).
- `annotation.gbk`: GenBank (`.gbk` from Prokka or `.gbff` from Bakta).
- `annotation.faa`: translated CDS proteins.
- `annotation.ffn`: annotated feature nucleotide sequences.
- `annotation.fna`: contig nucleotide sequences.
- `annotation.tsv`: feature table.
- `annotation.txt`: tool summary.
- `annotation.log`: command, tool version, exit status, stdout, and stderr.
- `metrics.json`: normalized run metadata and annotation statistics.
- `report.md`: human-readable run summary.
- `annotation_outputs.zip`: complete unmodified raw tool output.

Bakta runs may additionally produce `annotation.json`,
`annotation.inference.tsv`, `annotation.hypotheticals.tsv`, `annotation.svg`,
and `annotation.png`. These are optional so the same `runner.yaml` contract can
also validate Prokka runs.

## Reproducibility

Metrics record the selected annotator and executable version. For Bakta, they
also record the database path and, when available in Bakta JSON, its version
and type. Pin the executable and database versions when comparing multiple
genomes; annotations generated by different engines or database releases
should not be treated as directly comparable.
